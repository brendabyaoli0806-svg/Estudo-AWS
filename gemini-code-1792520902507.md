## 🚨 Desafios e Resolução de Problemas (Troubleshooting)

### 1. [Descrição curta do problema, ex: Instância EC2 marcando "Unhealthy" no Target Group]

* **O Sintoma:** O Load Balancer não conseguia redirecionar o tráfego para a instância e retornava erro 502/503.
* **Causa Raiz:** O Security Group da instância EC2 permitia tráfego HTTP apenas para o meu IP local, bloqueando as verificações de saúde (*health checks*) vindas do IP interno do ALB.
* **Como Solucionei:**
  1. Acessei o painel do **Security Group** da EC2.
  2. Editei as regras de entrada (*Inbound Rules*).
  3. Modifiquei a origem da regra HTTP (porta 80) para aceitar o ID do Security Group do ALB em vez do IP individual.
* **O que aprendi:** O ALB precisa de acesso de rede direto às instâncias do Target Group para validar a saúde da aplicação.

---

### 2. [Outro problema, ex: Erro 403 Access Denied no Amazon S3]

* **O Sintoma:** Ao tentar acessar o site estático hospedado no S3, o navegador exibia `403 Access Denied`.
* **Causa Raiz:** A **Bucket Policy** não permitia a ação `s3:GetObject` para acesso público.
* **Como Solucionei:**
  1. Desmarquei a opção *Block all public access* nas configurações de acesso do Bucket.
  2. Adicionei a seguinte política de leitura pública JSON ao Bucket:
  ```json
  {
    "Version": "2012-10-17",
    "Statement": [
      {
        "Sid": "PublicReadGetObject",
        "Effect": "Allow",
        "Principal": "*",
        "Action": "s3:GetObject",
        "Resource": "arn:aws:s3:::NOME-DO-SEU-BUCKET/*"
      }
    ]
  }
